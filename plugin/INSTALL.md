# 抖音备份 0.8.8 简洁版

无需安装 Node.js、Python 或后端。

## 安装或更新

1. 将扩展文件夹保存在固定位置，打开 Chrome 的 `chrome://extensions`（Edge 为 `edge://extensions`）。
2. 开启开发者模式，点击“加载已解压的扩展程序”，选择直接包含 `manifest.json` 的文件夹。
3. 已安装旧版本时，先暂停下载，再更新该文件夹并点击扩展卡片的“重新加载”。
4. 刷新抖音网页并登录。右上角默认出现黑白播放卡片图标；移上去出现喜欢、收藏、关注三个圆形入口，点击主图标展开侧栏。
5. 点击“选择文件夹”，在打开的小窗口中授权备份根目录；选择包含 `data` 的根目录。
6. 点击“下载喜欢”或“下载收藏”直接开始。下载关注列表时先选择作者。

## 0.8.8 缩短失败与暂停等待

媒体 403 直接记录失败，临时网络错误最多短重试一次。媒体冷却按地址来源处理，整轮结束直接保存结果。点击暂停后中止请求，等当前写入和状态日志保存即可。暂停时可在资料库手动更新报告，正常结束后自动更新。

## 0.8.7 清晰状态与恢复提示

运行中的首页入口显示对应任务阶段，点击查看当前进度。任务页统一准备、检查、下载、补下、等待和本轮结束状态；暂停原因会持续保留，并给出恢复操作。累计已备份包含历史作品，可能超过当前平台总数，悬停数量名称可查看解释。

关注支持名称和 UID 搜索，搜索后的全选只选择搜索结果；显示已选人数和选择保存状态。上次已选作者尚未加载齐时禁止启动；完整名单仍缺少的作者会明确提示，由你决定保留当前可选作者。

更多菜单进入“本地资料库”，可更新报告并查看报告保存位置。最小化继续下载；关闭插件会暂停；刷新或关闭抖音标签页会中断当前运行，已保存作品保留。每次下载仍从最新列表检查，最高画质作品跳过。新版本加载前先暂停旧任务，重新加载扩展并刷新抖音页面。

## 0.8.6 分类报告

本地库首页按“我的喜欢、收藏、我的关注”展示已备份作品数。喜欢、收藏直接浏览作品；我的关注先选作者，再查看作者作品，支持按名称或 UID 搜索。筛选重置保留当前分类，打开媒体优先使用对应分类下的视频或图片，封面不会抢占打开入口。统计、失败、画质和运行记录收进“备份详情”。重新加载扩展后，在菜单中“更新 HTML 看板”，再打开备份根目录的“本地库.html”。

## 0.8.5 快速跳过与自动补下

单项请求的响应等待、一次退避和重试共用 2 秒预算。正常持续传输的媒体继续下载；连续 2 秒无数据则让出位置。普通错误只影响当前文件；媒体 429 的冷却按下载域名单独记录，遵守 Retry-After，不让工作线程空等。

主列表读完且本轮下载处理结束后，自动刷新失败作品的地址，补下一轮。补下不重复读取列表、不增加检查数量；仍失败则保留原因，不循环补下。等待服务器冷却时会显示“等待补下”，可以随时暂停。下次点下载仍从最新列表开头检查，已完成最高画质直接跳过。补下统计可在“本地库.html”查看。

## 0.8.4 可读文件名

喜欢、收藏使用“作者 - 精简标题 [短ID]”；关注已有作者目录，内部使用“精简标题 [短ID]”。多文件作品目录同名，里面保留顺序编号。完整文案和完整 ID 仍在备份记录中，命名确定后保持稳定。历史库点击“整理备份”即可迁移，更新前先暂停任务，重新加载扩展并刷新抖音页面。

## 0.8.3 媒体分类目录

喜欢和收藏下面按“封面、视频、图片”分类；我的关注保留作者目录，再按三种媒体分类。单个文件直接使用作品 ID 命名，同一作品有多个视频或图片时，在相应类型目录内用作品 ID 建文件夹，按顺序编号。画质记录保存在内部元数据中，升级通过私有临时目录完成，验证后切换到固定文件名。历史库可用“整理备份”迁移；迁移时同步更新下载记录与离线看板路径。

## 0.8.2 重试与目录整理

- 媒体 403、网络临时错误与 429 最多自动重试 5 次，逐步延长等待，429 尊重 Retry-After。
- 喜欢、收藏、关注分别保存在 `data/喜欢`、`data/收藏`、`data/关注`；只有关注下面按作者分类。
- 同一作品跨来源出现时，从本地复制到对应分类，不重复请求媒体。重复清理保留分类边界。
- 设置中的“整理备份”会核对重复内容并整理分类路径。更新前先暂停下载、重新加载扩展并刷新抖音页面。

## 0.8.1 通高侧栏

展开后固定贴在浏览器右侧，从顶部到底部占满窗口，高度不再随首页/任务切换。桌面宽360像素，小窗口自动收窄；文件夹、下载入口和进度采用统一留白与对齐。收起后仍是可拖动的悬浮图标，环绕快捷入口和细进度环保留。

## 0.8.0 统一下载流程

每次点击下载都从当前列表开头检查到末尾。未下载的保存；已有最高画质的直接跳过；明确非最高的检查升级；未知画质不盲目重下。403/429仍在下载过程中自动进行有限重试与退避。

首页仅保留文件夹和喜欢、收藏、关注三个入口。任务页显示必要的数量与当前传输，底部只有“下载/暂停下载”。不再提供失败项重试、从头检查、作者检查点继续等分支按钮；关注仍记住作者勾选，按作者逐位处理，每次下载从第一位所选作者开始检查。

“数量与下载说明”、分页诊断、失败列表及首页统计说明均已移除。详细统计、容量缺记录、历史来源和错误原因统一在备份根目录的“本地库.html”查看，任务暂停/结束后自动更新。更多菜单仅保留更新 HTML 看板、整理备份及必要的旧库绑定。

## 0.7.9 仅对未达最高画质的记录触发升级

以下载时保存的画质标记为第一判断：已标记最高画质的媒体直接跳过，不因后续列表出现更大分辨率再次下载；只有标记为降级/回退的媒体才检查更优候选。候选确实优于现有版本才传输，未知标记也不自动重下。升级成功标记最高后，后续再次跳过。

## 0.7.8 自动升级画质与关注续下

- 再次读取到已有作品时，会比较列表候选与本地已记录画质。确认分辨率更高，或同条件下帧率/码率更好时，自动下载升级版；相同或更低画质不会重下。历史画质未知时不盲目重下全部媒体。
- 升级先写新文件，成功提交新引用后才清理旧文件；失败或暂停时原备份仍可用。升级单独计数，不增加唯一作品数或“本次新下载”。
- 关注选择保存在备份库，刷新或换电脑重新选择同一库后可恢复。当前作者的媒体处理完，再进入下一位；任务页显示当前作者位置。
- “继续上次任务”恢复名单、作者位置和待下载媒体；“重新检查所选作者”用于从头查新作品。新版本的未完成关注任务支持断点接续；旧版任务缺少作者检查点，会沿用选择并从头核对，已保存媒体自动跳过或升级。
- 喜欢、收藏仍每次从最新列表开始，避免遗漏新点赞、新收藏。

## 0.7.7 稳定进度与失败重试

- 修复进度环的旋转中心变化和偏移，始终与悬浮图标同心。外环跟随当前作品，多段媒体按作品段数累计，另一下载通道开始或结束不会影响它。
- 字节进度只更新当前传输和外环，不再反复重建整个任务页面，减少闪动与界面开销。
- 最高画质地址遇到403先短暂等待重试一次；仍失败则刷新作品地址一次，重新优先最高候选。持续失败会保留原因，不会无限循环。429继续遵守全局退避。
- “重试失败项”只重新获取失败作品的详情和媒体，不重新读取喜欢、收藏或作者作品列表，成功作品不会重下。“从最新开始检查”继续用于发现新内容。
- 精简首页和任务页文字，等待下载与未成功分别显示，数量说明默认折叠；报告标明本轮是否只做失败重试。

## 0.7.6 悬浮交互与数量显示

- 三个快捷圆按钮围绕主图标展开，自动朝屏幕内侧排列。拖动主图标可移动并记住位置，窗口改变大小后保持在可见范围。
- 主图标外圈以细蓝线显示当前媒体传输进度；列表检查或媒体大小未知时缓慢转动。已暂停时停止动画，不把历史备份/平台总数当作本轮百分比。
- “−”收起并继续下载；“×”先暂停、保存进度，再隐藏整个插件。悬浮展开时也有小“×”，隐藏后点击浏览器工具栏图标重新打开。
- 收藏数量先读取接口精确值，缺失时读取“我的收藏”的页面显示。平台显示“1.3万”时明确标为“约1.3万”；完整列表读取结束后，也会保留该轮可读取数量，未读完不推算总数。
- 媒体占用立即显示已知容量；历史记录不完整时显示容量加号和缺记录作品数，空闲时自动补统计。不会为统计读取整段媒体、删除文件或阻塞下载，缺少文件路径的旧记录会明确保留为未核实。

## 0.7.5 悬浮快捷入口与完整关注列表

- 默认最小化，不遮挡网页。鼠标移上主图标出现三个圆形快捷按钮；喜欢、收藏直接后台启动，主图标上的蓝点表示任务仍在运行。点击主图标查看进度。
- 关注先选作者：自动逐页读取所有可访问关注，没有 20 人或 100 人的产品上限。读完后可全选，搜索也覆盖完整列表；可提前勾选几位作者直接下载，此时停止读取剩余关注名单。
- 修正关注接口时间游标：下一页使用上一页最早关注时间，避免重复第一页导致漏人。平台人数与实际可读取人数分别展示；未读完或接口异常会提示重试，不会伪装成完成。
- 下载按作者逐位检查公开作品，每位作者的作品也持续分页，无 100 个作品上限。平台权限、私密/失效作品不属于可保证的下载范围。
- 已有任务运行时，快捷入口用于查看同来源任务；其他来源等待暂停或结束，避免同时写库。

## 0.7.4 每次从最新列表开始

每次点击下载都会从最新列表一路检查到末页，已保存作品自动跳过。遇到当前列表中的未完成文件时继续补传；不沿用旧列表游标，所以暂停期间的新喜欢也能发现。本地累计不归零，本次检查和下载数量单独展示。

## 0.7.3 分页修复（历史版本）

修复喜欢/收藏列表末页返回非零游标时被误判为异常的问题。本版保留非零末页修复；0.7.4 已改为每次从最新位置重查列表，媒体仍跳过或续传。可在任务页展开“列表读取诊断”。

## 使用方式

- 首页展示唯一已保存作品数、已完成媒体占用；喜欢和收藏入口分别展示平台总数及本地累计。任务页主区保留累计量，“本轮新下载 +N”单独展示。
- 本地累计包含已取消喜欢/收藏的历史作品，可以多于当前平台总数。已有作品按 ID 跳过，增量任务不会把本地累计数量归零；平台没有提供总数时显示未知。
- 喜欢、收藏、关注的来源可以重叠，不相加计算全库总数。
- 列表逐页读取，媒体最多两路并行下载，不再限制每次 100 个作品。
- 收起侧栏或返回首页，下载继续。刷新或关闭抖音页会中断任务，下次打开后点击当前任务并继续。
- 点击“暂停下载”会停止请求并保存进度。单段媒体支持服务器允许时按字节续传；媒体地址或规格改变时会重下该段。
- 右上角更多按钮进入备份库详情。“整理备份”在闲时核对媒体、补全旧库大小，并合并同作品同媒体段中内容相同的文件，保留各来源标签。
- 换电脑时需复制整个备份根目录，包括 `data/.appdata` 和未完成媒体的 `.resume.json`；然后重新登录并选择该目录。

## 报告、画质与限流

- 根目录的 `本地库.html` 是离线报告，包含数量、来源、最近任务、失败原因、画质和媒体文件入口。任务暂停/结束后自动更新；也可从右上角库详情手动更新。
- 下载优先尝试接口提供的最高候选，回退会记录原因；历史画质无法确认时保留原文件；能够确认更清晰版本时会自动升级。
- 429 会等待服务端要求的时间或按 15/30/60/120 秒逐步退避，并显示倒计时；最多自动重试 4 次，仍限流则保留进度暂停。点击继续可恢复。
- 403 与 429 分开处理；媒体仍无法访问时最多刷新一次详情地址，无法恢复的作品保留具体错误。

## 历史库与试用范围

- 支持读取旧版本的完成索引，历史媒体不会在选择文件夹时被扫描或删除。媒体大小未知时显示“待统计”，点击“整理备份”补全。
- 缺失账号归属的历史库需要在库详情核对并绑定；归属其他账号的库不能直接下载。无法识别的非空目录会提示选择空目录或核对历史记录。
- 本版主要重做三个下载入口、任务、作者选择和整理。旧的喜欢转收藏、私信自动点赞界面没有进入此试用包。
- 当前已通过合成接口和真实浏览器文件系统测试；未在你的真实抖音账号完成全量下载验收。抖音接口限制、失效作品或访问权限可能使任务部分完成。
- 数量来自备份记录，外部删文件后需整理核对。当前不要让后端、其他浏览器或其他电脑同时写入同一个备份库。
