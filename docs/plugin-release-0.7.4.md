# 0.7.4：每次从最新列表开始一轮检查

日期：2026-10-28。按用户提出的规则修订列表恢复行为。

## 统一规则

每次点击喜欢、收藏或已选作者下载，均创建新的运行记录，从列表开头检查到接口末页；不继承旧列表游标，也不因连续遇到已备份作品提前退出。用户可以自行暂停，下次仍从最新位置开始。它不是持续监听；本次起点之后才新增到列表头部的作品，会在下次点击时检查。

- 全库完成索引负责跳过已保存作品。同作品跨来源只补来源关系，媒体不重复下载。
- 当前列表中未完成的作品重新进入下载队列，已有完整媒体段跳过，未完成段在表示一致、服务器支持时按字节续传。
- 已取消喜欢或当前列表不再返回的旧队列项不会被强行补下；旧任务、部分文件和历史备份仍保留。
- 历史游标只作为诊断记录保存；关联前一次任务用于追溯，不用于本次列表起点。
- 429 尚未到期的冷却仍须遵守，换一轮运行不清除冷却。

## 展示

首页的全库和来源累计始终接续目录记录。任务页展示本次检查、本次已有跳过、本次新下载、待处理和需处理。无媒体传输、仍在读列表时显示“检查中”。暂停按钮明确为“从最新开始检查”。历史任务及其数量保留，本次数量不与旧任务累计混算。

已备份作品在每页检查时批量标记跳过，不进入媒体下载池；只有尚未完成的作品占用最多两路传输。

## 场景验证

| 场景 | 预期 |
| --- | --- |
| 首次备份 | 从最新检查到末页，保存未完成作品 |
| 下载一部分，隔一段时间有新点赞 | 新一轮从开头找到新点赞；旧文件不重下，遇到旧未完成文件续传 |
| 列表已读完但媒体失败，后来又有新点赞 | 重新读最新列表，同时重试仍在列表中的失败作品 |
| 上次已完成，之后再点赞 | 新一轮只传输新增或未完成媒体 |
| 总数没变，但取消了一些、又点赞了新作品 | 仍检查内容，不以数量差判断有无新增 |
| 取消后重新喜欢已有作品 | 命中全库 ID 索引，不重复保存媒体 |
| 连续发现已备份作品 | 检查继续递增，不擅自推断后面没有缺项 |

`test-backup-engine.mjs` 增加上述暂停/新增/同总数变化/重点赞/失败重试场景，以及旧任务历史保留和无重复媒体传输验证。旧 8,035 个记录场景现在重新从开头检查所有 8,048 个可读取作品，本次新增 0，累计仍为 9,012，原任务的 +271 历史记录保留。

`test-modern-ui.mjs` 在真实 Chrome OPFS 中验证暂停期间增加两个喜欢、完成后再增加一个喜欢、已完成媒体无二次传输、部分文件仍发送 Range 续传，并继续验证报告与整理。
