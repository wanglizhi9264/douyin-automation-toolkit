# 插件测试与发布手册

更新于 2026-11-10。适用 **0.8.11**。产品验收依据 [Spec v0.3](plugin-product-spec-v0.3.md)，实现依据 [技术基线](implementation-spec-0.8.7.md) 与 [0.8.8 实现变更](plugin-release-0.8.8.md) 和 [0.8.10 队列策略](plugin-release-0.8.10.md) 和 [0.8.11 修订](plugin-release-0.8.11.md)。旧版本清单与后端/私信审查另见 [历史发布手册](test-release-runbook-legacy.md)，旧的“100 条批次”“新目录二次确认”不作为当前下载流程要求。

## 1. 验证层级与状态

| 证据 | 证明什么 | 不能证明什么 |
| --- | --- | --- |
| 资源与语法检查 | 清单引用、版本、JavaScript 可解析 | 真实页面请求成功 |
| 核心模拟回归 | 队列、持久化、分页、重试、计数和媒体契约 | 任意平台账号、网络和磁盘都正常 |
| Chrome 合成页面 | DOM 交互、路径、选择恢复、浮层、静态报告 | 平台所有 API 当前都可用 |
| 真实备份报告检查 | 给定快照能分类展示与浏览 | 每个本地文件都经过内容验证 |
| 授权后的实机下载 | 指定账号、指定样本与目录的业务路径 | 全量不可见/下架内容也已备份 |

0.8.7 交付时已有核心、现代侧栏/关注选择和报告浏览器回归通过的记录，见 [更新说明](plugin-release-0.8.7.md)。本文 2026-11-05 的文档整理不冒充重新执行了一轮平台下载；再次发布需在当次结果中记录实际执行命令、范围与结果。

## 2. 自动检查

在 plugin 目录运行：

```sh
npm run check
npm run check:ui
npm run check:report-ui
```

浏览器测试需要本机 Playwright 和 Chrome/Chromium；已有依赖可用 PLAYWRIGHT_MODULE 与 CHROME_EXECUTABLE 指定，不能因环境缺失把跳过记为通过。文档单独修改检查相对链接、版本与代码常量即可，不要求为 Markdown 重跑全部下载测试。

| 业务 | 回归入口（plugin/scripts） |
| --- | --- |
| 资源/桥接/目录权限 | check-extension、test-content-bridge、test-download-target |
| 流水线、库锁、暂停、增量、失败收尾 | test-backup-engine |
| 平台/历史/本轮数量与悬浮进度 | test-backup-progress、test-floating-statistics |
| 响应预算、403/429、地址刷新、候选 | test-retry-quality、test-download-target |
| 来源分页和完整关注名单 | test-pagination、test-following-list |
| 分段和画质升级保留原件 | test-media-parts、test-quality-upgrade |
| 分类、迁移、可读命名 | test-library-layout、test-media-layout、test-readable-names |
| 状态与异常恢复文案、UID 搜索 | test-presentation |
| 现代侧栏、浮层、作者选择 | test-focused-ui、test-following-resume-ui（check:ui 汇总） |
| 报告模型、筛选、XSS、文件链接、窄屏 | test-library-report、test-library-report-ui |

上表脚本均为 .mjs。包内保留的旧侧栏合约测试属于兼容检查，其通过不能代表现代侧栏仍有私信点赞或旧一键流程。

## 3. 人工冒烟与关键反例

1. **文件夹**：新空目录直接初始化；现代/旧库数量能读取；未知非空目录不能覆盖；同名不同目录能切换；权限失效、外接盘拔出能保留原因并恢复。
2. **账号与锁**：账号不一致、历史归属未知、另一标签页占库、维护中打开，均有明确提示，不越过绑定或锁写入。
3. **查新**：第一次部分下载后新增点赞，再点下载从最新页开始；已有最高标记跳过；取消喜欢历史仍保留，累计可大于平台量。
4. **分页**：重叠作品不重计；非零末页可正确确认；游标循环、异常空页和接口失败不能标成完整扫描。
5. **传输**：单视频、多图片、多视频、live photo；暂停后字节和分段续传；错误 MIME、长度不符、206 偏移错误不能算完成。
6. **响应预算**：无响应、403、网络错误不能多轮长时间卡同一项；响应与首段数据共用预算；正常长视频持续传输超过 2 秒仍可完成。
7. **失败收尾与暂停**：失败项让出槽位，新队列为空时按冷却时间补位。验证扫描中及扫描结束后可多次重试，媒体 403 最多回队 10 次，404 不回队，429 冷却可暂停。暂停能取消排队请求，只提交状态日志，重开后仍能恢复已保存进度。
8. **限流**：媒体 origin A 冷却不全局阻塞 B；长 Retry-After 不占下载槽；列表限流可暂停；状态不能把仍在传输的文件显示为整体无工作。
9. **质量**：best/unknown 不盲目重下；明确降级且更好才升级；升级失败、暂停和写盘错误保留旧完整文件；成功不计新增。
10. **关注**：完整分页无 20 人/100 作品产品截断；名称/UID 搜索、结果全选和半选正确；刷新恢复选择；未加载的已选作者不被静默遗漏；缺失项要明确处理；不同作者传输不重叠。
11. **目录**：三来源分开，关注按作者；单文件平铺、多段顺序正确；封面独立；短名碰撞、Unicode 与迁移异常不覆盖其他作品；跨来源副本保留。
12. **UI**：默认收起，径向菜单在边缘仍可见、拖动不误触、细环同心；运行入口可查看任务；暂停原因重载后可恢复；任务按钮下不出现堆叠说明；最小化继续、关闭暂停、工具栏可再打开。
13. **报告**：首页三分类数量与来源索引一致；关注先作者后作品；重置保留分类；首链接优先本分类内容而非封面；50 条分页、搜索、CSV、路径/脚本转义；390/768/1440 宽度可用。
14. **错误提交**：模拟配额、head 损坏、journal 中断；有效旧链能恢复，无有效链报错；不得把损坏库初始化为空库；不能宣称所有未提交数据零丢失。

这些是验收项目，不是全部已经完成实机认证的声明。涉及真实账号操作与历史媒体整理，应按用户授权的目标执行，避免其他写入者并发写库。

## 4. 性能与执行时限

记录点击至首个请求、首个成功、扫描与传输耗时、吞吐、API 等待、磁盘写入、UI 响应；CPU、内存、p95 须说明机器、账号/库规模、网络、样本数与窗口。没有测量就写未测，不能把序列化微基准当作真实吞吐。

本项目交互式执行约定：资源/核心检查设约 30 秒上限；单个浏览器脚本约 30 秒，两项 UI 汇总约 60 秒；打包约 10–15 秒，网络推送约 20 秒。超时应查看输出并结束相关进程组、报告原因，不无限等待；这些是工作命令边界，不是用户下载任务最长时长。并非所有测试环境都内置这些上限，外部执行器也需约束。

## 5. 打包与交付

1. 只改文档时不修改插件版本或重打包；功能变更时同步 manifest/package、界面与报告版本和更新说明。
2. 按变更范围运行核心、UI/报告回归，记录失败和未测范围。
3. `npm run zip` 生成独立 portable 目录与 ZIP，仅包含运行清单、src 与安装说明；不得带登录态、浏览器 profile、媒体、后台数据或 node_modules。
4. 若交付固定目录 dist/douyin-toolkit-extension，同步后核对它与新构建的运行文件；检查清单中每个资源和新增模块都存在，ZIP 可解压且校验通过。
5. 按用户已授权的发布方式提交/推送；构建和真实备份记录不进入源码提交。单独写明提交结果，不用本地 commit 冒充远端成功。
6. 告知先暂停旧任务，再重新加载扩展、刷新抖音网页。页面关闭后任务不会独立持续下载，最高画质和已保存片段会在下一轮被跳过或续传。

真实库报告使用 `node scripts/update-local-report.mjs BACKUP_ROOT` 更新；该工具读取库元数据，写报告并在版本切换时备份旧报告，不迁移媒体。库维护脚本另行执行，必须与实际写库方错开。
