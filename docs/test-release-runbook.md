## 自动检查

插件：

```powershell
cd plugin
npm run check
node scripts/benchmark-performance.mjs
```

后端：

```powershell
cd backend
npm run check
npm run test:shares
```

私信真实页面验证：运行 `npm run douyin:probe-shares`。使用后端独立 Chrome 登录后，程序直接执行 `plugin/src/injected.js` 中的函数，只读扫描两轮，不点赞、不下载；输出保存在 `backend/data/shared-conversation-probe/`。会话 HTML、错误、截图保留在本机且忽略 Git。浏览器执行测试使用同一份插件源码，避免后端与插件实现漂移。合成页面回归通过不代表抖音真人流程通过，发布前仍需真实页面扫描与插件完整流程验收。

- `node scripts/probe-shared-conversation.mjs --full`：最多 200 轮的全历史只读尝试，不保证完整；未到历史边界、打开失败或点赞状态不明时返回非零退出码。
- `node scripts/probe-shared-conversation.mjs --full --like`：有真实点赞副作用，只能在用户明确授权后执行。仅点击明确未点赞的作品，并确认状态变化；已点赞不点击。
- 消息列表是旋转的虚拟列表。弹窗关闭后必须重新获取消息节点并恢复扫描位置；仅连续三轮处于历史边界且没有新增数据，才能标记历史扫描完成，达到轮数上限不算完成。
- `npm run test:shares` 包含弹窗关闭后消息 DOM 重建、滚动位置重置及已点赞跳过的运行时回归。

测试分层：源码匹配只证明约定存在；纯函数/模拟环境证明局部行为；合成 Chrome 页面证明 DOM/函数交互；真实页面证明当前账号的部分行为；已安装扩展、真实目录、全目标集合端到端才验证完整业务。不要把这些层次混成一次“全部通过”。真实点赞、收藏、下载均须取得用户对目标和副作用的明确授权。

最近保留的真实私信结果为 734 处理、104 新增点赞、418 已点赞、212 读取/打开失败、200 轮未到历史起点，身份键为空。结果不是成功全量验收。`ok:true` 只说明函数返回了结果，仍须核对 failures、unknownLikeState 和 reachedHistoryStart。

## 必测业务

1. 历史目录打开后直接显示索引数量，不全盘扫描。
2. 没有计数索引的旧目录扫描一次，生成 `download-counts.json`。
3. 历史目录选择后继续下载；新目录选择前出现确认提示。
4. 本地已有作品按 ID 跳过，不重复下载。
5. 带 `.resume.json` 的文件不算完成，并从已有字节继续。
6. 喜欢和收藏分页结束条件正常，异常空页不能标记完成。
7. 切换账号时阻止写入原账号目录。
8. 图文、多段媒体和封面目录正确。
9. 暂停后重新加载扩展，点击继续可以恢复。
10. 同 ID 同时存在于喜欢/收藏/关注：三个下载副本和状态独立，本地唯一总数只算一次，展示保留三个来源。
11. 浏览器数据库为空、历史索引和媒体存在：首页和重新导出的本地库不能丢历史数量；元数据未知须明确展示。
12. 重建索引：空目录、非作品目录、多段缺段、图文缺图、子目录 `.resume.json`、读取拒绝全部覆盖，未完成项不能计为完成。
13. 三份紧凑文件代次不同、写盘失败后再成功、强关后恢复、外部删文件：缓存可核对，失败队列可恢复，未落盘有明确提示。
14. 缺索引但旧 state 绑定其他账号：禁止迁移时先绑定/写入当前账号；未知所有者必须先确认。
15. 关注目标 101 条、默认 batch=100：本次下载 100 后必须报告剩余 1，不能宣称完整备份成功；中途失败也必须纳入结果。
16. 作者列表/作品 `hasMore=true` 空页、重复游标、非可信终点不能正常完成；部分同步不能作为全量目标。
17. 私信同昵称不同稳定 ID、身份键为空、原绑定不匹配：任何点赞前阻止；账号/目录不匹配亦不能先点赞。
18. 私信超时、暂停、关闭侧栏与重复启动：旧 run 必须确认取消，之后不再继续点赞、不允许重叠操作。
19. 喜欢、收藏或关注发生单条失败：一键不能只根据 phase 字符串报全部成功；后续阶段策略与最终部分完成状态明确。
20. 后端修改同一库后回插件：索引/缓存/快照一致；未完善互操作前不得并发写入。
21. 关注目录完成索引有 102 条、浏览器库只剩 1 条：同步作者后应跳过 102 个已完成副本，任务历史进度不得退回 1，也不能重复下载它们。

## 界面验收

- 下载页只显示目录、三个入口、必要数量、当前任务和基础设置。
- 本地数量与目录索引一致。
- 当前任务完成数不得回退到浏览器临时数据库中的较小值。
- 喜欢转收藏独立成第二个一级界面。
- 本地库优先展示唯一已完成、当前未完成/失败、更新时间；三个来源分开，累计来源量和唯一量不混用。
- 留存必须显示最近完整核对时间，不能称为“已删除数量”；未核对数显示未知/估算而非假精确零。
- 作者/描述优先，支持本地文件入口；详情再展示 ID、路径与画质。历史 HTML 不擅自删除。

## 性能验收

记录版本、机器、库规模、媒体类型、浏览器和网络条件。启动/开始/续传/暂停落盘/筛选翻页分别取样报告 p50/p95/p99 与样本数，同时观测浏览器/下载进程 CPU、内存峰值、磁盘读写字节和实际网络传输。主动节流和接口等待与 CPU/渲染耗时分开。

`benchmark-performance.mjs` 仅合成 JSON 序列化，不证明首屏或网络速度；当前 performance tracker 保留最近 2,000 样本，必须标明样本窗口，不得冒充长任务的全量 p95。无真实资源采样时写“未测”，不能用推测的内存数字作验收。
