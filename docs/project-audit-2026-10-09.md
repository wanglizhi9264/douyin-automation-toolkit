# 项目业务审查（2026-10-09）

## 结论与边界

当前插件 0.6.2、后端 0.3.0。下载器、逐段检查点、作用域复合键和轻量索引已有实现；本地展示、全量完成判定、目录迁移和私信副作用控制仍存在重要缺口。**自动检查通过不等于完整业务通过，不建议把“一键完整备份”标记为已验收。**

本次为源码审查、现有自动测试、无外部副作用的函数复现，以及既有真实运行结果核对；没有重新执行点赞、收藏或下载，没有改写 F 盘媒体、数据库及页面。审查不是所有抖音接口当前可用的认证，也不是 CPU/内存/网络的完整实机压力测试。

## 当前实际链路

1. 侧边栏读取平台资料与本地数量缓存；首屏不加载完整状态。
2. 单独下载选择/复用目录，读取完成索引，校验账号，创建当天首次任务的轻量元数据备份。
3. 喜欢、收藏从列表第一页重新对账；按 `scope:awemeId` 跳过已索引作品，必要时补详情，写媒体和逐段检查点。
4. 关注作者先同步关注与所选作者作品，但下载队列只取配置的一个批次，默认 100 条。
5. 完成媒体后更新内存索引与数量，约 1.2 秒合并写盘；安全收尾生成快照、展示库和本地 HTML。
6. 一键链路先处理私信点赞，再依次调用三个下载任务；当前没有统一的结构化“全量完成”结果。

## 数据必须区分的口径

| 数据 | 当前用途 | 不能代表什么 |
| --- | --- | --- |
| 平台个人资料数量 | 平台当前公布的总数 | 可访问作品数、当前待下载唯一作品数 |
| `download-index.json` | 各作用域完成 ID 集合，快速跳过 | 实时媒体完整性证明；外部删文件后不会自动感知 |
| `download-counts.json` | 首屏数量缓存与喜欢留存核对 | 独立事实源；必须与完成索引一致 |
| IndexedDB `scopedItems` | 当前浏览器任务、作品元数据 | 整个目录的历史作品总量 |
| `download-state.json` | 兼容与安全收尾快照 | 启动必须加载的数据、实时计数 |
| `db_*.json`、`本地库.html` | 派生展示数据 | 下载是否完成的权威依据 |
| `likedArchived` | 本地喜欢中不在最近完整可读喜欢集合的部分 | 已被作者删除的确切数量 |

作用域完成条目总量是三个集合的长度之和；本地唯一作品数是三个集合的并集大小。一个作品可同时属于喜欢、收藏、关注，来源关系不能因为展示去重而丢失。某作品在收藏已备份，不等于喜欢目录也有副本。

## 已确认问题与整改验收

严重级别：P1 为误操作、误判完成或恢复风险；P2 为展示一致性和性能问题。以下均为未关闭问题，不是本次已修复清单。

| 编号 | 级别 | 证据/现状 | 要求与验收 |
| --- | --- | --- | --- |
| A01 | P1 | `report.js:buildLocalLibraryHtml` 把除 bookmarked 外的来源全部映射为 liked；以下关注记录被展示为喜欢，已用实际函数复现 | 明确支持三个 scope 与未知来源；关注不可归为喜欢；同 ID 多来源保留关系 |
| A02 | P1 | `persistDownloadArtifacts` 使用 `getAll(items)` 与缓存快照生成展示；当前任务传入的 `folderRecord.items=[]`，没有加载/补全历史元数据；`buildLocalDatabase` 又只从当前浏览器 items 重建 | 索引提供总量，完整元数据单独维护；未知历史元数据不能造成已备份记录消失；浏览器库为空仍可重建完整本地概览 |
| A03 | P1 | 关注下载 `.slice(0,batchSize)`，默认 100；普通队列逐条失败后也可能置“已完成”；一键只检查字符串“异常/已暂停”，喜欢/收藏失败数也未纳入总成功条件 | 返回 `{status,scanComplete,pending,failed,completed}`；批次结束与全量完成分开；剩余队列或失败未处理不得宣称完整备份成功 |
| A04 | P1 | `collectWorkIds` 直接把子目录名加入完成集合，不检查子目录的 `.resume.json`、缺段或空目录；嵌套未完成目录的函数复现被计为完成 | 重建索引须验证所有必需媒体段；空目录、非作品目录、任意段续传标记都不能算完成；读取错误不得伪装空目录并覆盖旧可信索引 |
| A05 | P1 | `getDownloadIndex` 迁移时用当前浏览器缓存账号赋给已有媒体目录，而不是先核对历史目录账号；首屏也未先核对账号就展示目录数 | 迁移优先读取旧账号证据；无法确认所有者要求用户明确确认；账号不符不得提前写索引或把其他账号数量当当前账号 |
| A06 | P1 | 私信会话键可能为空；同昵称按分数选择；`sharedConversationBinding` 在 `SCAN_SHARED_CONVERSATION(likeMissing:true)` 返回后才校验；一键目录校验也在点赞后 | 先只读解析稳定用户/会话 ID、校验目标与账号/目录，再允许点赞；身份缺失/不符时零副作用 |
| A07 | P1 | `events.js` 请求超时只删除 Promise；扫描器没有取消协议；私信阶段不检查下载暂停标记。超时/停止后页面任务可能继续点赞 | 引入 runId 与协作取消；超时/暂停使页面任务退出并确认，确认前不启动第二次运行；不能把“停止后续下载”当成“点赞任务已经停止” |
| A08 | P1 | `flushCompactWrites` 在写入前清空 entries，失败后没有回填重试；索引、数量、进度并行独立写，非原子事务 | 失败保留最新待写状态并可重试；UI 显式报告未落盘；采用 generation/一致性核对，不能承诺关闭/崩溃也能保证刷新 |
| A09 | P2 | 数量与索引独立维护；`updateLocalFolderCount` 使用 max，不能纠正删除后的过高计数；F 盘收藏缓存与索引相差 1 | 数量从同代索引派生；显式“核对本地库”负责外部修改后的校正；不能每次开侧栏全盘扫描 |
| A10 | P2 | 下载首页关注 total 仅来自本地完成缓存，常导致 pending=0；收藏 pending 用平台总数减本地累计；这些集合不一定同口径 | 首屏未完整对账时标“估算/未核对”，不显示假精确 0；待下载按当前任务目标集合减该 scope 完成集合计算 |
| A11 | P1 | 作者分页遇到空页、`hasMore=false` 或 cursor=0 任一条件就退出，与喜欢/收藏可信终点策略不一致 | 覆盖 `hasMore=true` 空页、游标不前进及异常终点；不能把中途空页当完整同步成功 |
| A12 | P2 | 单作品 manifest 和派生 db_videos 仅以 awemeId 为键，跨 scope 写会覆盖路径/状态；后端只更新旧 state/log，不维护插件紧凑索引 | 媒体元数据与 scope 副本拆分；保留各 scope 路径；插件/后端统一写入协议后才能宣传完全互通，当前禁止并发写同一库 |
| A13 | P2 | `sidebar/app.js` 超过 4,000 行，混合 UI、账号、目录、分页、下载、计数、导出；分页多处全量读取 IndexedDB | 先抽纯统计与任务结果，再抽 archive repository、扫描器和任务编排；使用 scope 索引/分批查询。CPU Worker 不能解决全量 I/O 或状态不一致 |
| A14 | P1 | 关注通用下载分支读取 localIndex 用于绑定，却筛选 IndexedDB downloadStatus 组队，没有像喜欢/收藏那样按该 scope 完成集合对账；`countDownloadedInScope` 也只数浏览器记录 | 所选作者作品须先与 following 完成索引核对，再过滤待下载；浏览器记录缺失/过期不能重新下载已完成副本，历史进度使用目录完成索引 |

## 测试结果与缺口

- 插件 `npm run check`：13 个检查脚本通过；部分是源码匹配/契约断言，不是浏览器端到端。
- 后端 `npm run check`：语法与两个下载测试脚本通过。
- 后端 `npm run test:shares`：合成 Chrome 页面执行实际插件源码的回归通过，包含重建 DOM、恢复位置及已点赞不反向切换；本次没有访问真实账号。
- 无副作用函数复现：following 被映射为 liked；带嵌套续传标记的作品目录被扫描为完成。这两个反例证明全绿测试仍有盲区。
- 本机 11,319 条合成记录、20 次 JSON 序列化基准：完整格式化快照约 8.02 MB，p95 26.29 ms；紧凑快照约 6.55 MB，p95 20.10 ms；实时检查点 135 B，p95 小于计时展示精度。**仅序列化基准，不是磁盘、浏览器首屏、下载吞吐或资源占用测试。**
- 既有真实私信结果文件：734 个处理卡片，104 新增点赞、418 已点赞、212 打开/读取失败；`reachedHistoryStart=false`，200 轮上限，conversationKey 为空。没有证明完整历史扫描或后续三阶段完整下载通过；失败不能统称已删除。
- 当前性能样本只保留最近 2,000 条。p95 是该样本窗口的阶段耗时，不是整个长任务的无损累计统计；CPU、进程内存与网络吞吐仍需另做实机测量。
