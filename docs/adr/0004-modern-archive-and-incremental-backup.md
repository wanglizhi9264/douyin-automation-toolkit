# ADR-0004：现代 v2 库、增量检查与分类副本

- 状态：Accepted
- 文档整理日期：2026-11-05
- 实现基线：插件 0.8.7，追溯 0.7.0–0.8.7 已落地变化
- 替代范围：ADR-0001 的现代库主键约定；ADR-0002 的旧状态文件与 cursor=0 终止细节；ADR-0003 的旧路径、候选上限和直接跨后端互操作承诺。保留重新对账、媒体分段和成功段检查点原则。

## 背景

产品逐步改成从最新列表持续增量保存，喜欢/收藏/关注各有物理目录，报告按三类浏览；旧 IndexedDB scopedItems、数字文件名与列表批次约定已不能完整描述现代库。

## 决策

1. v2 `works[id]` 表达唯一作品，sources 保留来源，`files[path]` 表达实际副本及媒体段；task 仍限定单个 scope。不能按 ID 丢掉来源，也不能把多来源复制误当作品数增加。
2. 喜欢、收藏、关注物理分开；已有内容跨来源本地复制。统计唯一数按 ID，磁盘占用按实际已登记完成文件。
3. 正常每次启动从最新页重新检查，记住作者选择不等于从旧 cursor 开始；保留内部兼容接口不增加对应 UI 分支。
4. 以 v2 受校验快照、journal 与双 head 为事实源；旧索引仅导入、报告仅派生，写入失败暂停。
5. 媒体最高标记是升级资格门槛；明确降级/回退且候选更好才升级，未知不盲下；升级提交前保留原件。
6. 单项响应和一次短重试有 2 秒预算，媒体限流按 origin 隔离；主列表结束后只补一轮，不无限卡同一项。该预算不截断持续正常传输。
7. 分页依据受验证的接口语义与确认策略，不统一要求末页 cursor 为零；部分列表读取不冒充全量成功。

## 后果

代价包括跨来源副本的真实空间占用、下一轮重复读取列表、未知历史画质不自动提升，以及仍依赖运行中的抖音标签页。收益是操作入口统一、新点赞不被旧游标遗漏、计数口径可解释、失败不会长时间阻塞后续媒体。

后端独立工具必须另行适配 v2 提交和维护协议，不能因共用解析器就直接并发写库。完整契约见 [产品规格](../plugin-product-spec-v0.3.md) 与 [技术实现](../implementation-spec-0.8.7.md)。
