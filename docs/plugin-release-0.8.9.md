# 抖音备份 0.8.9

列表扫描独立运行，两路下载优先消费新作品。新队列为空、当前来源仍在扫描且有空闲下载位时，消费者取一个冷却已结束的失败作品。候补队列只记录作品 ID 和最早可重试时间，与新作品队列分开。取出前检查该作品当前无传输，避免重复占用两个位置。

临时错误可以在扫描期间多次尝试。失败后冷却依次为 1、2、4、8、16、30 秒，此后保持 30 秒。429 最早重试时间同时遵守服务器冷却。每次回队重新获取作品详情和地址，已完成片段可复用。403 在刷新地址后仍被拒绝则停止候补，404、410 与不支持作品保留失败结果。主体媒体遇到临时错误直接让出位置，候补的每个媒体段在一次调度中最多发起一次请求。

重试不重复累计已检查作品。等待冷却时保留失败记录，取出重试后转为处理中，成功后更新结果。列表扫描结束或当前关注作者扫完后，只收尾已有传输与新作品队列，不再启动候补。暂停中止请求并保存日志。

运行结构与暂停实现见 [0.8.8 实现变更](plugin-release-0.8.8.md)。数据与文件格式见 [技术实现基线](implementation-spec-0.8.7.md)。
