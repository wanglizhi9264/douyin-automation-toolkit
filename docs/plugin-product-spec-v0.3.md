# 抖音备份产品规格 v0.3

更新：2026-11-05。适用插件 **0.8.7**；以当前现代侧栏和离线报告为范围，替代 [v0.2 讨论稿](plugin-product-spec-v0.2.md) 中冲突的规则。实现对应 [技术规格](implementation-spec-0.8.7.md)，验收对应 [测试与发布](test-release-runbook.md)。本文记录当前已实现的产品约定，不能据此推断任意账号都能完整导出平台全部内容。

## 1. 产品定义与边界

把当前账号的喜欢、收藏、所选关注作者作品保存到用户授权的本地文件夹。核心路径是“选择文件夹 → 选择来源 → 直接下载 → 查看结果”，没有全列表扫描后的确认关卡。下载不会自动点赞、收藏或操作私信。

扩展使用当前抖音网页登录态；运行依赖该标签页。列表逐页读取，与媒体下载交叠。最小化继续运行；关闭插件先暂停再隐藏；刷新、关闭网页或浏览器会中断运行，不能当成独立后台下载服务。

## 2. 页面与交互

| 页面 | 用户能看到什么 | 主要操作 |
| --- | --- | --- |
| 首页 | 保存文件夹、下载喜欢、下载收藏、下载关注 | 选择或更改文件夹；直接启动喜欢/收藏；进入作者选择 |
| 当前任务 | 平台总数或所选作者数、累计已备份、本次新增、检查/跳过/待下载/未成功、当前传输 | 运行时暂停；停止后点击下载重新查新 |
| 作者选择 | 名称与 UID、搜索、全选或全选搜索结果、总已选人数、选择保存状态 | 多选后下载；处理不再可读取的历史选择 |
| 本地资料库 | 本地库.html 的保存位置、更新报告、整理备份、必要的旧库账号绑定 | 更新报告或闲时整理 |
| 悬浮状态 | 可拖动主图标、围绕展开的喜欢/收藏/关注入口、当前媒体细进度环 | 快捷启动、展开任务、最小化或关闭 |

首页正常状态不堆数量卡、下载说明、历史任务条或维护说明。当前运行来源的入口显示“来源 · 当前阶段”，点击查看已有任务；其他来源在运行期间不可启动。加载备份库时显示载入状态。文件夹、账号等异常持续展示恢复指引。

任务底部只有一个下载或暂停按钮；没有“从头开始”“继续旧游标”“只重试失败项”等并列分支，也不在按钮下面追加说明区。错误指引位于状态区。数量提示与关闭/最小化行为通过对应控件提示说明。

## 3. 文件夹与账号

1. 用户通过目录授权窗口选择备份根目录，系统优先定位上次目录或视频目录。
2. 空目录直接初始化；可识别现代库或历史库读取已有记录，不要求额外确认一次开始下载。
3. 非空但无法识别备份记录的目录不能当作空库覆盖，应提示核对或选择空目录。
4. 同一库绑定账号 UID；账号不同拒绝下载。历史归属未知的库需在资料库页明确绑定，不能按当前登录态默认为该账号。
5. 下载、整理或报告更新使用库时不可直接切换目录；外接盘断开或权限失效时重新连接、选择并授权原目录。

## 4. 一次下载如何进行

### 喜欢与收藏

每次点击下载，从对应列表的最新一页检查到本轮可读取末页。因此前一次只下了一部分、期间新增点赞/收藏、取消后再次喜欢、列表重排，下一次都能重新核对。检查已保存作品不等于重新传输媒体。

- 未完成作品：下载未完成媒体段，已有完整分段可跳过。
- 已标记最高候选成功：直接跳过，不因后来出现更大候选而再次下载。
- 明确标记降级或回退：只有找到确实更好的候选才升级。
- 画质未知的历史记录：不盲目重新下载整个历史库。
- 来源新增但媒体已保存：本地补齐对应分类副本，避免重复请求媒体。

### 我的关注

作者名单自动分页读取，没有前 20 位的展示上限，也没有只下 100 个作品的产品限制。用户必须选择作者，不默认下载全部关注。

选择保存到备份库；再次进入可恢复。搜索支持名称和 UID；搜索后的全选仅作用于搜索结果，半选状态区分部分勾选。名单尚未加载齐且有未出现的已选作者时禁止启动，避免悄悄漏掉上次选择。完整读取后仍缺少的已选作者会明确提示，由用户点击“保留当前可选作者”决定是否移除。

所选作者逐位处理，前一位首轮媒体处理结束再进入下一位；单个作者内部最多两路媒体下载。每次正常启动从第一位所选作者的最新作品开始检查，记住选择不代表自动继承远端游标。失败项在主轮结束后统一补下；补下阶段也不让不同作者的传输重叠。

## 5. 重试、等待与结果

普通临时错误或媒体 403 最多短退避重试一次；响应等待、首段数据、这次退避与重试共用 **2 秒预算**，预算不够时直接让出位置。失败先记录，继续后面的作品。

正常持续传输的大文件不受 2 秒总时长限制；连续 2 秒无新数据会中止当前媒体尝试，保留可续传信息。刷新作品地址与第一段媒体响应也共享起始预算。此规则不是对整个作品、整轮扫描、磁盘写入或全部接口的硬实时承诺。

媒体 429 按下载地址 origin 单独冷却，遵守 Retry-After；等待超过当前预算时暂缓该项，其他 origin 可继续下载。列表接口有独立节流与限流处理。主列表完整读完、首轮队列清空且未暂停时，自动对可重试失败作品刷新详情、补下一轮；补下不重读来源列表、不增加已检查数量，仍失败则保留记录，不循环补下。

| 状态 | 用户含义 |
| --- | --- |
| 正在准备 / 检查已有作品 | 确认账号、列表和本地记录，不代表重复下载 |
| 准备下载 / 下载中 | 准备当前文件，或已收到媒体数据 |
| 等待限流解除 / 等待补下 | 正在遵守服务器冷却；已知期限时显示倒计时 |
| 补下中 | 主轮已结束，自动补一次失败作品 |
| 本轮完成 | 本轮可读取列表已处理，没有未解决的失败或待处理 |
| 本轮结束 | 仍有失败、不支持项或来源错误；不表示全部成功 |
| 已暂停 | 可手动暂停，也可能由账号、文件夹、写盘等异常触发，异常应保留原因 |

磁盘空间、权限、账号、库锁、进度记录写入失败等阻断问题不能伪装成普通媒体失败。持久化过的任务来源错误在重载后恢复说明；尚未写入任务的启动错误不能承诺跨重载保存。

## 6. 数量与进度口径

| 字段 | 定义 |
| --- | --- |
| 平台总数 | 接口或页面上次观测值；近似值带“约”，不可用显示未知，不伪造 0 |
| 累计已备份 | 该来源的历史已完成作品数，包含已取消喜欢/收藏的历史，因此可能大于平台当前总数 |
| 本次新增 | 当前运行新保存的作品数；升级画质不计新增 |
| 已检查 | 当前运行去重检查的作品数；分页重叠和补下不重复累计 |
| 已跳过 | 已有记录并符合跳过条件的作品数 |
| 待下载 | 当前已发现且尚未结束的作品，包含准备、传输、重试等待与提交；不是完整列表的剩余数 |
| 未成功 | 当前运行失败与不支持作品数；补下成功后从失败转为成功，不按尝试次数累计 |
| 唯一已备份 | 全库已完成作品 ID 去重数；三个来源数不能相加当作唯一数 |
| 已完成媒体占用 | 已登记完成文件大小之和；跨来源实际副本占用分别计算，缺历史大小记录时明确标“+” |

运行计数应满足：已检查 = 本次新增 + 画质升级 + 已跳过 + 待下载 + 失败 + 不支持。它不是“平台总数减本地累计”的差值。列表未读完时使用不定进度；悬浮细环表示当前选定媒体作品及其分段进度，不表示全库覆盖率。

## 7. 文件布局与命名

```text
备份根目录/
  本地库.html
  data/
    喜欢/{封面,视频,图片}/
    收藏/{封面,视频,图片}/
    我的关注/作者名_UID/{封面,视频,图片}/
    .appdata/                         # 库元数据、内部暂存、维护记录
```

喜欢、收藏用“作者 - 精简标题 [短ID]”命名；关注已有作者目录，文件名省略作者。单个文件直接放在媒体分类下；同类型多个片段用同名作品目录，内部按 01、02 顺序命名。完整作品 ID 始终保存在记录中；文件短名不承担唯一身份。

标题最多 30 个字素，作者最多 14 个字素，清理链接、提及与话题噪声，缺失时回退为未命名作品/未知作者。短 ID 从后 8 位开始，冲突时扩到 12、16 直至完整；首次确定后保存，标题/昵称变化不反复改名。

当前约定允许同一作品在喜欢、收藏、关注各有对应目录副本；作品身份和统计仍去重。跨来源副本属于有意保留，不能被整理误删为重复项。该规则覆盖早期“全库媒体只保留一份”的讨论方向。

## 8. 离线报告与维护

报告首页以我的喜欢、收藏、我的关注为入口，数字表示各来源已备份作品。喜欢/收藏直接浏览作品，关注先按作者分组再看作品，支持搜索。作者 UID 缺失时保留历史分组与未知说明，不能伪造身份。

分类内重置筛选保留当前来源和作者。打开媒体优先选择对应分类的已完成视频或图片，封面不抢占主入口；旧记录缺路径时明确提示。列表分页、搜索、状态/画质筛选、详情与 CSV 可离线使用。去重总量、占用、运行、失败与画质信息放在默认收起的备份详情。

报告是生成时快照，不是实时任务控制器。暂停/结束后自动尝试更新，也可在资料库页手动更新；库忙时不可并发生成。报告不改变下载状态，也不从页面直接发起失败重试。

整理在空闲且持有库锁时执行。维护同步更新路径、引用和报告，保护不同片段、画质和跨来源副本；历史无法确定的记录保留待核对，不以缺信息为理由删除媒体。

## 9. 产品验收边界

必须覆盖新目录、旧库、账号不匹配、增量点赞、分页异常、两路传输、暂停与重载、失败补下、画质升级保护原文件、作者缺失选择和分类报告。自动化、合成浏览器与真实平台验收分别记录，不能把页面能渲染推断为全量备份成功。具体检查矩阵见 [发布手册](test-release-runbook.md)。
