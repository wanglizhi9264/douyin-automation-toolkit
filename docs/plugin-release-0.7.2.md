# 0.7.2：本地报告、429 冷却与画质追踪

日期：2026-10-28。范围为新下载流程及 v2 本地报告。

## 429 与继续下载

0.7.1 只有媒体候选间短重试，未遵守服务端冷却时间。本版为列表、详情和媒体共用一个异步冷却协调器：

- HTTP 429 优先遵守服务端 `Retry-After`（秒数或 HTTP 日期），并使用 15 / 30 / 60 / 120 秒指数等待，加入最多 20% 随机偏移。实际等待不早于服务端要求。
- 冷却期间停止发起新请求，已经开始的传输可以完成。429 重试同一媒体候选，不直接切低画质。
- 最多自动重试 4 次，仍限流则保留队列并暂停。点击继续时仍遵守未到期的冷却记录。界面显示原因和倒计时。
- 暂时性网络错误及部分 4xx/5xx 最多重试 2 次。403 单独处理：所有媒体候选仍不可用时最多刷新一次详情地址，不通过更换身份或网络地址绕过限制。

依据：[RFC 6585 §4](https://www.rfc-editor.org/rfc/rfc6585#section-4)。

## 画质与证据

候选按分辨率优先，同分辨率按码率、帧率、大小排序，保留接口候选和兼容候选。优先最高候选不表示所有作品均能提供或下载原始最高画质。

新记录保存实际候选、当时最高候选、候选名次、回退原因及失败/冷却时间。报告区分最高候选成功、同分辨率回退、降级、历史最高候选未记录、仅图片。既有媒体不因升级重复下载，缺少历史证据时保持未知。

## 本地报告

以 v2 目录记录为权威，旧状态、视频/描述/作者数据库补充详情。展示全库唯一已备份、待处理失败、待处理队列、来源累计与平台上次总数、最近一轮新增/跳过、失败原因、实际画质、媒体路径与原作品入口。来源不相加作为总数，平台总数不与历史累计相减。

列表每页渲染 50 个作品，支持多来源、状态、画质、全文搜索、详情和 CSV。离线打开，不自动请求网络。旧报告首次替换时保存在 `data/.appdata/backups/report-before-0.7.2-*.html`。报告标注生成时间与记录更新时间，运行状态为快照记录。

任务暂停/结束及整理结束后闲时更新报告；库详情可手动“更新本地报告”。更新与下载互斥，报告失败不会改写下载结果。

## 验证

- `npm run check`：兼容检查及新引擎、数量、退避、画质、报告模型运行时回归。
- `npm run check:ui`：合成接口、真实 Chrome OPFS，验证增量、暂停续传、整理与报告保存。
- `npm run check:report-ui`：离线 Chrome，204 个作品的分页、多来源、画质/失败/搜索、CSV、本地链接、XSS、390/768/1440 宽度，以及实际目录报告的加载。
- 退避回归覆盖秒数/日期、指数延迟、取消、冷却恢复、重试耗尽暂停且保留队列、最高候选 429 后原候选重试及真实降级原因。

真实库操作只读取元数据并更新 HTML 报告，没有新增真实下载、点赞或删除媒体。真实平台对重试策略的效果仍由用户继续试用验证。
