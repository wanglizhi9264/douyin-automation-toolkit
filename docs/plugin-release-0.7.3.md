# 0.7.3：修复非零末页游标导致的暂停

日期：2026-10-28。

## 实际原因

对停住的喜欢列表做了两次只读请求：请求 `max_cursor=1783556134000, min_cursor=0`，均返回 HTTP 200、`status_code=0`、`has_more=0`、`max_cursor=1783511616000`，最后一页 13 个作品。

0.7.2 要求无下一页且游标为 0 才视为结束，将正常末页判为异常，并在作品入队前抛错。这不是限流或媒体下载失败。只读核对确认 13 个作品均已在目录中完成，但尚未纳入本轮已检查数量。

## 修复

- 明确无下一页是结束信号，不要求零游标。非零或缺失末页游标会增加一次同断点只读确认。
- 空页有下一页且游标前进时继续跨页；连续空页有上限。
- 游标不前进、循环、矛盾终点或缺少有效字段时有限重试，无效响应不被当作完成。
- 异常页的有效作品先保存并处理，再暂停列表读取；断点保留在最后安全位置。
- 记录最近 12 条分页诊断及确认终点，侧栏和报告可展开查看。重试阶段有明确提示。
- 完成文案限定为本轮可读取列表，不将平台总数与返回数量之差断言为丢失或未下载。

## 验证

`test-pagination.mjs` 覆盖非零 13 条末页、确认期间恢复有下一页、空页推进、卡页恢复、异常页有效数据、循环、字段缺失、空页预算、取消及三个下载来源。

`test-backup-engine.mjs` 复现 8,035 个已检查（271 新下载、7,764 已有）、喜欢累计 9,012 的场景。末页接入后已检查为 8,048、已有跳过为 7,777，本轮新下载仍为 271、累计仍为 9,012，新增媒体传输为 0，任务正常结束。

测试使用脱敏响应结构和合成作品 ID，不改写真实任务，不触发真实下载、点赞或删除。
