# 抖音备份 0.8.3

公开目录统一为以下结构：

```text
data/
  喜欢/
    封面/作品ID.jpg
    视频/单视频作品ID.mp4
    视频/多视频作品ID/01.mp4、02.mp4
    图片/单图作品ID.jpg
    图片/多图作品ID/01.jpg、02.jpg
  收藏/（同上）
  我的关注/作者名_UID/（同样的封面、视频、图片分类）
```

多文件判断按媒体类型分别计算，封面独立于正文图片；静态图+Live Photo 视频分别归入图片、视频。每类按片段顺序编号，兼容多个视频、图文、动态照片；已完成片段保留，补齐剩余片段时目录不变。图片格式按已知 MIME/扩展名保存，避免把已知 WebP 改成 JPG 后缀。

画质参数留在元数据；画质升级先下载到私有暂存目录，完成并核对后再切换固定文件名。原文件保留到新媒体完成，失败不覆盖原文件。跨来源的必要分类副本继续保留，作品数仍按作品 ID 去重。

新下载有封面时单独保存，图文封面从本地首图复制；封面不可用不把正文视频判成失败。历史整理只搬迁已有文件，不为旧作品联网补封面。

离线迁移沿用可恢复事务：同盘移动前保存意图，批量更新媒体引用、别名与作者目录，途中退出可重放；旧路径再次成为正式路径时清除过时别名，避免引用循环。未完成作品中已经写好的片段也迁移，未知目标冲突先备份。保留整理前状态、隔离目录及迁移清单，更新 HTML 后核对所有已知文件。

自动化覆盖：单视频、多段视频、图片集、Live Photo 编号冲突、封面分类和复用、分段补齐、私有暂存升级、目标冲突保留、旧库迁移、途中恢复与别名不成环。
